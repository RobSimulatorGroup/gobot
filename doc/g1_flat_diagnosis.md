# G1 平地退步诊断

2026-11-08。对比 `g1_29dof_8gpu/model_final.pt` 与 `g1_shared_gobot_seed42/model_final.pt`，
两者均为第 18,000 次 PPO 更新（iteration 17999）。模型留在 118；本次未复制新 checkpoint 到本机，未启动训练。

直接原因已复现：**新版策略的零转向响应带有持续向左的偏置**，身体前进速度仍接近指令，
但朝向不断改变，世界坐标中的轨迹因此弯出路线。尚不能把该偏置的形成唯一归因于某个训练改动。

## 实验与结果

118 的八张 GPU 正在运行用户的 mjlab 训练，本次使用 CPU MuJoCo 做短诊断，避免占用训练 GPU。
同一套当前 Gobot 代码、相同 G1 模型、固定命令、关闭推力/域随机化/观测噪声，seed 71，
每组 4 个环境。之前的 GPU 评测已显示新版平地块 30/30 偏离；本次 CPU 也复现了该失败。
下面的角度与转速是 CPU 诊断值，不冒称为 GPU 逐步重放结果。

两组实验：

1. 粗糙地形网格中的四个平地块，从 x=-3.25 m 开始，命令 (0.8, 0, 0)，最多 12 秒。
   旧模型 4/4 穿越，新模型 0/4 穿越、4/4 偏离，无跌倒。约 8.02 秒的平均横向位移分别为 0.295 m 与 2.782 m；
   当时平均航向偏差分别为 0.19° 与 63.76°。穿越/偏离只统计首次事件，后续轨迹不追加成功。
2. 独立连续平地，运行 8 秒，每档转向指令重新 reset。下表转速是 2–8 秒均值，角度是 8 秒末值。

| 命令 vx=0.8 m/s、wz=0 | 旧模型 | 新模型 |
| --- | ---: | ---: |
| 身体前向速度 m/s | 0.7731 | 0.7791 |
| 身体侧向速度 m/s | +0.0358 | -0.0681 |
| 实际世界航向转速 rad/s | -0.0011 | **+0.1397** |
| 8 秒末平均航向偏差 | 0.38° | **63.85°** |
| 8 秒末平均横向位移 | 0.296 m | **2.769 m** |
| 角速度奖励率（已乘权重，未乘 dt） | 1.5448 | 1.5359 |

转向指令响应（前进 0.8 m/s）：

| 转向指令 rad/s | 旧模型实际平均转速 rad/s | 新模型实际平均转速 rad/s |
| --- | ---: | ---: |
| -0.7 | -0.0832 | -0.0063 |
| -0.5 | -0.0591 | **+0.0414** |
| -0.25 | -0.0305 | +0.0915 |
| 0 | -0.0011 | **+0.1397** |
| +0.25 | +0.0262 | +0.1930 |
| +0.5 | +0.0593 | +0.2382 |
| +0.7 | +0.0929 | +0.2731 |

新旧模型对转向命令都跟踪不足，旧模型在零指令附近碰巧保持直行；新模型则出现正方向零偏。
新版在 -0.5 rad/s 的右转指令下，2–8 秒仍平均左转。纯站立原地转向的响应同样很弱：
指令 ±0.6 rad/s 时，两边实际转速都接近零。这说明转向控制本来就是该训练配方的薄弱项。

## 排除的输入/加载问题

每档指令、每步均核对：

- `CheckpointPolicy` 和严格加载同一 actor_state_dict 的 RSL-RL 原生 `MLPModel`，动作最大误差为 0。
- actor 观测中的三维命令与实际设置值最大误差为 0。
- actor 的角速度观测与 transition_state 的身体角速度最大误差为 0。
- 新旧运行保存的奖励、控制、机器人、PPO 配置相同；差异是评测设置与源码摘要。

因此本次没有发现 checkpoint 加载器、命令槽位或角速度观测接错。这里不是对所有物理/backend
代码的完备证明，但复现已跨越 GPU 正式评测与 CPU 小规模诊断。

## 为什么奖励没有明显区分直行和走弯

当前两边对齐的角速度奖励为：

`2 * exp(-(wx² + wy² + (wz - command_wz)²) / 0.5)`

在上述零转向平地样本中：

| 平均平方误差分量 | 旧模型 | 新模型 |
| --- | ---: | ---: |
| wx² + wy² | 0.05291 | 0.03894 |
| (wz - command_wz)² | 0.08311 | 0.09984 |

新版减少了滚转/俯仰摆动，抵消了部分偏航误差；两者合成后的角速度奖励率只相差约 0.6%。
奖励没有直接惩罚累计世界航向偏差或横向偏移。持续小幅偏航可在数秒内积成几十度，
但其瞬时奖励差距很小。速度奖励又是在身体坐标中计算，朝向转了仍能保持“向自己前方走”。
这是能解释该失败的目标函数局限，不等于已经证明优化器究竟在第几轮选择了这种步态。

## 诊断性干预

仅在诊断时增加航向反馈 `command_wz = clip(-2 * heading_error, -0.7, 0.7)`，
保持同一个新策略权重，四个平地块从 0/4 穿越变成 4/4 穿越；运行到 12 秒的航向仍约 19°，
横向位移约 1.69 m。这说明策略还能响应较强纠偏，并不是无法完成前进动作。
但该反馈改变了任务输入，只用于定位问题，不能作为原评测通过成绩，也不是已完成的训练修复。

将速度指令转换为世界坐标的诊断同样可以让轨迹穿越，但机器人朝向仍持续旋转；
因此仅改速度坐标系不足以解决转向跟踪问题。先站立两秒再走也没有消除持续偏航。

## 对训练成因仍存在的不确定性

共同地形改动改变了初始地形难度分配和 reset 流程，接触计时也改成固定 dt；
这些变化会改变采样轨迹。两轮都是 seed 42，不代表两次训练接收到完全相同的数据。
目前只有一个训练种子，没有分别只改采样、只改计时的对照，不能断言是哪一项引发零偏。

本轮 3500–3999 更新的平均训练回报约 31.65，最后 500 次约 16.79。
指令课程与地形难度同时改变，所以仅凭这条曲线不能断言早期策略直行更好。
旧保存逻辑在关闭评测时仅覆盖 latest.pt，历史 checkpoint 未保留，无法回查零偏首次出现的时间。

## 已实施的诊断改进

- 评测新增 `yaw_rate_bias_rad_s`，区分带方向的持续转动和正负摆动。
- 直行测试新增平均航向偏差、平均绝对航向偏差和最大航向偏差，正确展开 ±180° 边界。
- 逐 episode 记录航向变化并在首次结束后冻结；不把 autoreset 当成纠偏恢复。
- 定期保存增加 `model_000499.pt` 等带编号 checkpoint 和 manifest，保留 latest.pt 作为恢复入口。
  即使 `--no-eval` 也能回查中间策略。已有覆盖文件不能追溯恢复。

本次改动不调整奖励或强行给策略增加导航控制。下一项应是针对零转向偏置和转向响应的训练实验，
同时单列累计航向偏差；不要继续用总体 reward 或地形等级替代直行能力的判断。

原始诊断脚本及轨迹保留在 118 的 `gobot/logs/g1_flat_diagnosis/`：`diagnose.py`、`response.py`、
`new.json`、`previous.json`、`new_response.json`、`previous_response.json`。
